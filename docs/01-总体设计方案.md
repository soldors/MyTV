## 0. 事实核查（方案依据，均可核对）

| 对象 | 核查结论 | 证据 |
|---|---|---|
| LibreTV 原仓库 | `bestK/LibreTV` 已删除（GitHub API 返回 404） | api.github.com 实测 |
| LibreTV 现主仓库 | `LibreSpark/LibreTV` v2.15.0（上游开发仓 `bestZwei/LibreTV-Next`），13,988★，2026-09-27 仍在更新，**已重构为 Next.js 15 + React 19**，不再是纯静态页 | GitHub API + package.json 实测 |
| LibreTV 存储 | **无服务端数据库**：播放记录/收藏走浏览器 IndexedDB（dexie）；服务端只做无状态代理 | 其 package.json（dexie/zustand）与 README |
| LibreTV 代理层 | 服务端代理带 SSRF 防护（含 DNS 解析后校验）、会话 cookie 签名（PROXY_SECRET）、UA 伪装、超时重试；支持苹果CMS采集站接入与 TVBox 订阅导入；另有直播（M3U/EPG）模块 | 其 README |
| LibreTV 协议 | **AGPL-3.0**（网络提供服务也须开源） | GitHub license 字段实测 |
| LunaTV | `MoonTechLab/LunaTV`，Next.js 14 + TS + Tailwind，功能完整（多用户、云端收藏/播放记录、管理后台、豆瓣、跳过片头片尾、流式搜索） | GitHub API + README 实测 |
| LunaTV 存储抽象 | `src/lib/db.ts` + `src/lib/types.ts` 的 `IStorage` 接口约 25 个方法（播放记录/收藏/用户/搜索历史/管理员配置/片头配置）；实现仅 redis / kvrocks / upstash / localStorage | types.ts 实测 |
| LunaTV 部署 | **官方仅支持 Docker**，存储无 D1/KV 适配；`db.ts` 顶部无条件 import node-redis 客户端，直接上 Workers 会挂 | 其 README「本项目仅支持 Docker…部署」+ db.ts 实测 |
| LunaTV 协议 | **CC BY-NC-SA 4.0**（禁商用、相同方式共享） | 其 README |
| Cloudflare 部署方式 | `@cloudflare/next-on-pages` 已弃用；2026 年官方路径是 **OpenNext（@opennextjs/cloudflare）部署到 Cloudflare Workers**，绑定（D1/KV/R2）经 wrangler 注册、`getCloudflareContext().env` 访问 | Cloudflare 官方文档 / opennext.js.org |
| 苹果CMS 接口 | 采集 API 形态 `{base}/api.php/provide/vod/?ac=list`、`?ac=detail&ids=`、`?wd=搜索&pg=分页`；TVBox 订阅 JSON 中 `type:1` 即苹果CMS采集站，可批量导入 | LibreTV README 数据源章节 |

**结论**：两个上游目前都不支持 Cloudflare 直部。LibreTV 服务端架构天然 Workers 友好（无状态代理），但无服务端数据库；LunaTV 有完整数据模型但背着 Redis/Docker 包袱；两者界面均不满足要求。结合点是：**新建工程，移植 LibreTV 的服务端逻辑（代理/源管理/会话），前端界面全部自研，数据层用 D1 实现 LunaTV 的 IStorage 语义**。

## 1. 目标定位

一句话：**服务端移植 LibreTV 的代理/源管理/会话逻辑（AGPL），前端界面全部自研，数据层用 D1 实现 LunaTV 的 IStorage 语义，OpenNext 部署到 Cloudflare Workers；视频零存储，全部走第三方采集站直链。**

「结合两者 + 界面自研」的取舍：

| 移植自 LibreTV（仅服务端） | 取自 LunaTV（仅数据语义） | 自研 | 两者都不取 |
|---|---|---|---|
| 代理层（SSRF 防护、UA 伪装、超时重试） | IStorage 数据模型（用户/收藏/播放记录/搜索历史/跳过片头/管理员配置） | **前台界面**（首页/搜索/详情/播放/我的）+ **独立后台管理界面** | LunaTV 的 Redis 系存储与 Node 依赖 |
| 苹果CMS 源管理 + TVBox 订阅导入逻辑 | 多用户体系与云端同步语义 | 视觉与交互设计 | LunaTV 的 next-pwa 等旧构建链 |
| 签名会话（cookie + PROXY_SECRET） | 管理后台的产品形态（源配置后台可改） | — | 任何视频/海报的本站存储（仅缓存） |
| 直播/IPTV 服务端代理（可选保留） | — | — | 两个上游的整套前端 UI |

## 2. 总体架构

```
浏览器
  │  HTTPS
  ▼
Cloudflare Workers（Next.js 15 · OpenNext）
  ├─ 前台界面（自研）   首页 / 搜索 / 详情 / 播放 / 我的 /（直播）
  ├─ 后台界面（自研·独立布局与鉴权）  数据源 / 用户 / 站点 / 内容运营 / 系统
  ├─ API 路由层    /api/search  /api/detail  /api/user/*  /api/admin/*  /api/proxy
  ├─ 代理层        苹果CMS 采集站代理（SSRF 防护、UA、超时重试、熔断）、图片代理
  ├─ 存储抽象层    IStorage（LunaTV 语义）── D1Storage 实现
  └─ 绑定          D1（主库） · KV（热缓存） · R2（冷缓存，可选） · Cache API（边缘）
                    │
                    ▼
        第三方：苹果CMS 采集站（视频信息+m3u8 直链）、豆瓣（推荐/评分）
```

要点：Workers 不收发视频流本体；m3u8 由浏览器直连源站，仅当源站有 Referer 防盗链时才走代理重写。

## 3. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Next.js 15 + React 19 + TS + Tailwind | 基座自带，OpenNext 支持成熟 |
| 播放器 | ArtPlayer + hls.js（+ mpegts.js 若留直播） | 两上游共识方案 |
| UI 组件 | 待拍板（见 #12） | 界面整体自研，上游 UI 不沿用 |
| 部署 | OpenNext（@opennextjs/cloudflare）+ wrangler → Workers | 2026 官方路径；next-on-pages 已弃用 |
| 数据库 | Cloudflare D1（SQLite） | Workers 原生绑定；免费额度够个人站 |
| 缓存 | KV（搜索/详情热数据）+ Cache API（图片/列表边缘缓存） | KV 保跨边缘一致性，Cache API 零成本兜底 |
| 对象存储 | R2（可选，一期不启用） | 仅在图片代理缓存量起来后启用 |
| 认证 | cookie 签名会话（PROXY_SECRET 派生）+ D1 users 表 | 沿用基座机制，无新依赖 |

| 资源 | 用途 | 免费额度（约） | 本项目预估 |
|---|---|---|---|

| Cache API | 图片/热门列表边缘缓存 | 免费 | 主力图片缓存 |

## 5. 数据库设计（D1 草案）

对照 LunaTV `IStorage` 的 25 个方法映射为 7 张表（DDL 为草案，评审后细化）：

| 表 | 关键列 | 说明 |
|---|---|---|
| `users` | name PK, password_hash, salt, role, created_at | 站长/普通用户；密码加盐哈希 |
| `play_records` | user_name, source, vod_id, title, pic, index, total_time, play_time, save_time | 联合唯一键 (user_name, source, vod_id) |
| `favorites` | user_name, source, vod_id, title, pic, save_time | 同上唯一键 |
| `search_histories` | user_name, keyword, created_at | 每用户保留上限 N 条 |
| `skip_configs` | user_name, source, vod_id, intro_start, intro_end, outro_start, outro_end | 跳过片头片尾 |
| `api_sources` | key PK, name, api_url, detail_url, is_adult, weight, enabled | 苹果CMS 源，后台可增删改 |
| `admin_configs` | id（单行）, config_json, updated_at | 站点级配置（公告、过滤开关等） |

说明：搜索缓存不建表，放 KV（带 TTL，免清理）。

## 6. 存储方案分工

| 数据 | 去向 | TTL/策略 |
|---|---|---|
| 用户/收藏/播放记录/配置 | D1 | 持久 |
| 搜索结果、影片详情 | KV | 搜索 30min、详情 6h（可拍） |
| 豆瓣/采集站海报图 | Cache API →（量大后）R2 | 边缘 24h |
| 视频流 | 不存储，浏览器直连 m3u8 | — |

## 7. 苹果CMS 接口集成

1. **源模型**：`{ key, name, api: ".../api.php/provide/vod", detail?, adult, weight, enabled }`，存 `api_sources` 表，管理后台维护；支持粘贴 TVBox 订阅 URL 批量导入（沿用基座已实现逻辑）。
2. **代理**：全部经 `/api/proxy` 服务端转发——采集站普遍无 CORS；沿用基座 SSRF 防护（拒绝内网/保留地址 + DNS 解析后校验）、UA 伪装、超时（8s）重试（1 次）。
3. **聚合搜索**：多源并发 `?wd=`，按 weight 排序、同名去重；流式回前端（基座已具备此体验）。
4. **缓存**：搜索/详情结果进 KV；源站故障时短路（连续失败 N 次熔断 M 分钟，参数可拍）。
5. **播放**：解析 `vod_play_url`（`线路$集$地址` 格式）出集数列表；m3u8 优先直连，Referer 防盗链源走代理重写。
6. **内容过滤**：成人源默认过滤（黄过滤词库沿用基座），开关放管理后台。

## 8. 认证与多用户

- 站长账号由环境变量 `PASSWORD` 派生；普通用户注册（可关）→ D1 `users`。
- 会话 = HMAC 签名 cookie（`PROXY_SECRET`），Workers 内用 WebCrypto，无 Node 依赖。
- 未登录仅放行图片代理（沿用基座策略），防代理被白嫖。
- 收藏/播放记录登录后写 D1，多端同步；未登录回落 IndexedDB（基座现状），登录时合并。

## 9. 界面设计：前后台分离、视觉品质与响应式

### 9.1 前后台分离

**形态**：同一 Next.js 工程内用 route group 物理分区——前台 `(site)/` 与后台 `(admin)/admin/` 各自独立布局、独立导航，互不共享页面骨架；`middleware.ts` 对 `/admin/*` 与 `/api/admin/*` 强制管理员会话鉴权，非管理员返回 404（不暴露后台存在性）。管理员从「我的」页进入后台。

```
app/
├─ (site)/            前台布局（顶部导航 + 页脚）
│   ├─ page.tsx       首页
│   ├─ search/ detail/ play/ my/ （live/）
└─ (admin)/admin/     后台布局（侧边栏工作台，无前台导航）
    ├─ page.tsx       仪表盘
    ├─ sources/ users/ site/ content/ system/
```

**后台设置内容清单**（「对应前台内容」列即前后台的内容对应关系）：

| 分组 | 设置项 | 对应前台内容 / 说明 | 期次 |
|---|---|---|---|
| 数据源 | 苹果CMS 源管理 | 增删改、权重、成人标记、启用开关、探活 → 决定搜索/播放的可用结果 | 一期 |
| 数据源 | TVBox 订阅 | 订阅 URL 管理、导入、手动/定时刷新 → 批量维护上一条 | 一期 |
| 数据源 | 直播源 | M3U/XMLTV 管理 → 直播页（随直播里程碑） | 二期 |
| 用户 | 用户列表 | 审批注册、禁用、删除、重置密码 | 一期 |
| 用户 | 角色 | 站长 / 管理员 / 普通用户 | 一期 |
| 站点 | 基本信息 | 站点名、公告、LOGO → 前台顶栏与公告条 | 一期 |
| 站点 | 访问控制 | 密码门禁、注册开关、注册审批开关 → 登录/注册页行为 | 一期 |
| 内容运营 | 成人过滤 | 开关 + 自定义过滤词 → 搜索/列表结果 | 一期 |
| 内容运营 | 搜索行为 | 最大页数、流式开关 → 搜索页 | 一期 |
| 内容运营 | 首页推荐位 | 榜单源选择（豆瓣榜/手动置顶）→ 前台首页分区 | 二期 |
| 缓存/代理 | 缓存管理 | TTL 调整、手动清除 KV 缓存 | 二期 |
| 缓存/代理 | 代理参数 | 超时/重试/UA（一期用环境变量兜底） | 二期 |
| 数据 | 备份导出 | D1 导出/导入 | 二期 |
| 系统 | 状态 | 版本、各源可用率、绑定自检 | 二期 |

### 9.2 视觉品质

- 对标消费级流媒体产品（Netflix/Disney+/Emby）的观感，不做工具站式简陋界面。
- 默认暗色主题（观影场景），预留亮色切换；设计令牌（色板/圆角/阴影/间距/字号阶梯）统一管理，全站一致。
- 设计提案（#10/#13）升级为高保真方向稿：2 个方向 ×（首页 + 播放页）× 三端视图，评审后再开发。
- 细节标配：海报骨架屏与加载占位、hover/焦点态、页面过渡动画、空态与错误态均有设计。

### 9.3 响应式三端适配（已拍：手机 + 电脑 + 平板）

移动优先开发，Tailwind 断点（sm 640 / md 768 / lg 1024 / xl 1280）：

| 端 | 宽度 | 导航形态 | 海报网格 | 播放器 |
|---|---|---|---|---|
| 手机 | <768 | 底部标签栏（首页/搜索/我的），触控目标 ≥44px | 3 列 | 全屏沉浸，原生全屏 API |
| 平板 | 768–1279 | 顶部紧凑导航，横竖屏自适应 | 4–6 列 | 页内宽屏，控制条加大 |
| 电脑 | ≥1280 | 顶部导航，内容限宽 ~1600px | 6–8 列 | hover 快捷操作，键盘快捷键 |

后台管理界面桌面优先、平板可用、手机基础可用（表格降级为卡片）。

## 10. 协议与合规

- **AGPL-3.0**（LibreTV）：移植/复制其代码并对外提供网络服务 ⇒ 必须开源并提供源码入口。个人/内部使用可接受，页脚挂源码仓库链接即可。
- **CC BY-NC-SA 4.0**（LunaTV）：只借鉴数据模型与产品语义，**不直接复制代码**；若要复制则全项目须遵守非商业 + 相同方式共享。
- 站点页脚保留两上游的免责声明（不存储、不制作任何视频内容，内容合法性由数据源负责）。

## 13. 主要风险

| 风险 | 应对 |
|---|---|
| 采集站失效频繁（上游生态常态） | 多源 + 熔断 + TVBox 订阅随时换源 |
