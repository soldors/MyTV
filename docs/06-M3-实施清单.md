| KV 绑定 | `wrangler.toml` | 命名空间 `abf7efb92b754675b4656438a3d9c4f2`，绑定名 `KV`，本地/远程均接入 |

## 2. 关键实现事实（排雷记录）

1. **Workers 会取消悬挂 Promise**：`void kv.put(...)` 在响应返回后会被运行时取消，KV 写入静默丢失——必须 `await`（或在流关闭前完成）。
2. **L1 与高频词门控的交互是设计语义**：60s 内的重复搜索命中内存提前返回、不计数不写 KV；只有 L1 过期后的再次搜索（真·高频词）才触发 KV 写。测试时两次请求必须间隔 >60s 才能观测到写。
3. `wrangler kv key list --local` 与 preview 的 miniflare 状态路径不互通（CLI 显示空），验证以应用读写与 sqlite 直查为准。
4. workerd 对不可达域名的 fetch 抛 `internal error; reference=...` 文本——路由侧已正常捕获为该源失败（非崩溃），仅文案不友好，已映射。

## 3. 本地验收（2026-09-29，全部真跑）

| 用例 | 结果 | 证据 |
|---|---|---|
| 搜索 L1 | ✓ | 同 key 第 2 次 `X-Cache: memory`（8ms） |
| 搜索高频词门控 | ✓ | 60s 内第 2 次命中 L1 不写 KV；L1 过期后第 3 次触发写入（sqlite 见 `search:m3diag…` 键，TTL 30min） |
| **重复搜索命中 KV（核心验收）** | ✓ | 重启（清内存）后同 key 搜索 `X-Cache: kv`，且回填 L1（下一次 memory） |
| 详情 KV | ✓ | 请求后 sqlite 出现 `detail:…\|61205` 键（TTL 6h）；二次请求 `X-Cache: memory` |
| 熔断触发 | ✓ | 坏源连续 3 次失败后，第 4 次搜索 **9.9ms** 短路，错误含「已熔断，300s 后自动重试」 |
| 熔断标记 | ✓ | failures 条目带 `circuitOpen: true`（前端可区分提示） |
| 回归 | ✓ | 正常搜索/详情/记录/收藏流程不受影响；typecheck 通过 |
